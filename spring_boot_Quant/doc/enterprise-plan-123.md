# 퀀트 투자 플랫폼 고도화 실행 계획 (벤치마크 반영)

작성일: 2026-02-10  
대상: `spring_boot_Quant`  
목표: "보기 좋은 관리자 화면"이 아니라, **실제 수익 창출에 필요한 실행 플랫폼**으로 전환

---

## 0. 문제 정의

현재 문제는 3가지다.

- Grid/필터/레이아웃 사용성이 낮아 실무 속도가 떨어짐
- 화면은 많지만 "무엇을 위해/어떤 순서로 행동해야 수익이 나는지"가 약함
- 백엔드가 영속/확장/전략 검증 관점에서 MVP 수준이라 실전 운영 신뢰성이 부족함

---

## 1. 벤치마크 요약 (Salesforce 제외)

## 1.1 기관형 운용/집행 플랫폼

- Charles River IMS: OMS/OEMS + 컴플라이언스 + 운영 워크플로우
- LSEG TORA: 클라우드 OEMS, 리밸런싱, TCA
- Bloomberg AIM: OMS + 포트폴리오 + 운영 통제
- Aladdin: 리스크 조정 수익 관점의 통합 운용
- SimCorp One: front-to-back 데이터 정합

## 1.2 트레이더 UX/자동화 플랫폼

- Interactive Brokers TWS: 액티브 트레이더 중심 주문 UX
- TradingView: 차트/시그널/알림 중심 의사결정 UX
- QuantConnect: 연구-백테스트-실거래 파이프라인
- Alpaca: paper/live API 기반 자동매매 검증

---

## 2. 제품 목적 (명확화)

이 플랫폼의 목적은 아래 1문장으로 고정한다.

- **리스크를 통제하면서, 실행 품질을 높여, 누적 수익률을 극대화한다.**

이를 위해 사용자에게 항상 아래 순서를 제공해야 한다.

1. 오늘의 시장/포지션/리스크 상태 파악
2. 실행 가능한 액션 우선순위 확인
3. 주문/체결 실행 및 예외 처리
4. 체결 품질(TCA)과 손익 기여도 평가
5. 다음 실행 규칙 개선
